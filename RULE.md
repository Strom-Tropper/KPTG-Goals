## Directory Structure

Do not create new directories outside the existing structure without prior discussion with the team.

```
src/
├── animations/       # Spine animation wrappers (class pattern, extends Container)
├── app/              # PixiJS app initialization, app context
├── components/       # Reusable UI components, split by domain
│   ├── base/         # BaseModal — shared foundation used everywhere
│   ├── component/    # Small, generic UI components
│   ├── game/         # Components tied to game logic
│   ├── hub-game/     # Components belonging to hub/lobby
│   └── main-game/    # Components belonging to the main game scene
├── modules/
│   └── game/
│       ├── engine/   # Pure game logic, no UI dependency (includes game.assets.ts)
│       ├── handlers/ # WebSocket request/response handlers
│       └── ws/       # WebSocket setup
├── scenes/           # Top-level scenes (GameScene.ts)
├── shared/
│   ├── constants/    # Game settings and shared constants
│   ├── types/        # Shared TypeScript types
│   └── utils/        # Pure utilities (math, time, helpers...)
└── systems/          # Cross-cutting systems (audio, ...)
```

```
raw-assets/           # Source of all assets — do NOT delete arbitrarily
public/
├── assets/           # AssetPack output — do NOT commit to git
├── manifest.json     # Auto-generated by AssetPack — do NOT commit
└── css/              # Static CSS files — committed
scripts/              # Validation scripts
.husky/               # Pre-commit hooks
```

## File Naming

There is no "any name goes" rule. Each file type has its own convention and must be consistent.

| File type | Convention | Example |
|---|---|---|
| Scene | `PascalCase.ts` | `GameScene.ts` |
| UI Component | `PascalCase.ts` | `BaseModal.ts`, `JackpotPanel.ts` |
| Spine / animation wrapper | `PascalCase.ts` | `BossCharacter.ts`, `Spinner.ts` |
| Constants | `camelCase.ts` | `settings.ts` |
| Utils / helpers | `camelCase.ts` | `math-utils.ts`, `time.ts` |
| WS handlers | `camelCase.requests.ts` | `game.requests.ts` |

File names must match their contents. `GameScene.ts` exports `createGameScene` or class `GameScene`, not any other name.

## Asset Pipeline

All assets flow in one direction only:

```
raw-assets/  →  npm run assetpack  →  public/assets/ + public/manifest.json
```

**Mandatory rules:**

- **`raw-assets/`** is the single source of truth. Edit assets here only.
- **`public/assets/`** and **`public/manifest.json`** are auto-generated output. Do not edit manually, do not commit to git.
- After adding or modifying files in `raw-assets/`, always re-run `npm run assetpack` to sync.

**AssetPack folder name tags:**

| Tag | Meaning |
|---|---|
| `{copy}` | Copy files as-is, **bypasses all processing pipes** (used for lang folders) |
| `{m}` | Create a named bundle in the manifest |
| `{nomip}` | Do not generate mipmaps |
| `{tps}` | Texture packer sprite sheet |

Current folder structure:
```
raw-assets/
├── en{copy}/               # Lang bundle — copied as-is, no compression
├── vn{copy}/
├── th{copy}/
├── loading{m}/             # Game bundle — own manifest bundle
├── main-game{m}{nomip}/
├── main-scene{m}/
└── popup{m}/
```

**Manifest (`public/manifest.json`):**

- Auto-generated by AssetPack — do not edit by hand.
- In production builds, the Vite plugin inlines the manifest directly into JS — no manifest file exists in `dist/`.
- In dev, the manifest is fetched from `./manifest.json` at runtime.

## Localization (Lang Sync)

This is the most commonly overlooked area. Whenever a new image is added to one language, **all other languages must have the equivalent file**.

**Structure inside `raw-assets/`:**

```
raw-assets/
├── en{copy}/          # Reference language (English)
├── vn{copy}/          # Vietnamese — must mirror en/ exactly
└── th{copy}/          # Thai — same rule
```

**Mandatory rules:**

- `en{copy}` is the reference. Every other language must have the corresponding files (different extensions are allowed — e.g. `en` uses `.webp`, `vn` uses `.png`).
- Adding a file to `en/` → immediately add the equivalent to ALL other languages. No deferred tasks.
- Removing a file from `en/` → remove the equivalent from all other languages.
- File names (ignoring extension) must match exactly across all languages.

`validate-lang.mjs` enforces this automatically before every commit.

## Pre-commit Hook — All Steps Must Pass

Three steps run automatically on `git commit`. If any step fails, the commit is rejected.

```
1. node scripts/validate-lang.mjs      # Check lang sync
2. node scripts/check-asset-sizes.mjs  # Check file sizes
3. npx lint-staged                     # Lint + format code
```

**`validate-lang.mjs`** — fails if:
- A file exists in `en{copy}` but is missing in another language
- A language has extra files not present in `en{copy}`

**`check-asset-sizes.mjs`** — applies to files in lang folders (`en`, `vn`, `th`...):
- File > 5 MB: **hard error**, commit blocked
- File > 2 MB: warning, commit allowed but should be optimized

**`lint-staged`** — runs ESLint and Prettier on staged files. Fix with `npm run lint:fix` if errors occur.

Never bypass hooks when they fail. Fix the root cause.

## Build Process

```bash
# Local development
npm run dev

# Full production build (validate + assetpack + lint + tsc + vite)
npm run build:prod

# Build for dev/staging environment
npm run build:dev
```

`build:prod` runs the full pipeline in order:
1. Validate lang
2. AssetPack (generate `public/assets/` and `public/manifest.json`)
3. ESLint
4. TypeScript check
5. Vite build (inlines manifest into JS, removes manifest from dist)

Do not skip any step. If a step fails, fix it before proceeding.

## Working with PixiJS

### Creating sprites and containers

Use standard PixiJS APIs. Pixi.js v8 is used — do not use deprecated v7 patterns:

```typescript
// Correct — PixiJS v8 API
import { Sprite, Container, Texture } from 'pixi.js';

const icon = new Sprite(Texture.from('ui_button.png'));
icon.anchor.set(0.5);

const group = new Container();
group.addChild(icon);

// Wrong — deprecated v7 pattern
const icon = new Sprite(resources['ui_button'].texture);
```

### Spine Animation

Each Spine animation has its own class file in `src/animations/`, extending `Container` or `CompositeSpine`. Never use the raw Spine API directly in a scene or component.

```typescript
// Correct — use the existing animation class
import { BossCharacter } from '@/animations';
const boss = new BossCharacter({ ... });

// Wrong — raw Spine API in scene code
import { Spine } from '@esotericsoftware/spine-pixi-v8';
const spine = new Spine(skeletonData);
```

### Component Layers

- `components/base/` — foundation, usable anywhere (modals, overlays)
- `components/component/` — small, generic UI, no game logic
- `components/game/` — tied to game logic
- `components/hub-game/` — belongs to hub/lobby
- `components/main-game/` — belongs to main game scene

Do not put components in the wrong layer. `JackpotPanel` should not be in `base/`.

### Accessing Assets

Sprite sheets are loaded at startup and accessed via `gameAssets` from `@/modules/game/engine/game.assets`. Do not hardcode raw `Assets.get()` calls in components.

```typescript
// Correct — typed access via gameAssets
import { gameAssets } from '@/modules/game/engine/game.assets';
const sprite = new Sprite(gameAssets.Popup.textures['popup_panel.png']);

// Correct — localized assets loaded from lang bundle use Sprite.from()
const text = Sprite.from('text_balance.png');

// Wrong — bypasses the asset loading system
const sprite = new Sprite(Assets.get('popup_panel.png'));
```

## Coding Style

- **No comments** unless the reason is genuinely not readable from the code itself. Good variable and function names replace comments.
- **No `any`** if it can be avoided. If unavoidable, document why.
- **No dead code** — deleted code must be fully removed, not commented out.
- Use the `@/` alias for imports instead of long relative paths.
- Export functions rather than classes for scenes and components. Spine/animation wrappers use classes (they extend `Container`).

## Git — What to Commit and What Not to

**Commit:**
- `src/` — all source code
- `raw-assets/` — original asset sources
- `scripts/` — validation scripts
- `public/css/` — static CSS
- Config files: `vite.config.ts`, `.assetpack.js`, `tsconfig.json`, `eslint.config.*`, `.husky/`

**Do not commit:**
- `public/assets/` — generated by AssetPack, already in `.gitignore`
- `public/manifest.json` — generated by AssetPack
- `dist/` — build output
- `node_modules/`
- `.env`, `.env.*` — contains secrets
- Binary files > 5 MB in lang folders

If generated files were accidentally committed, use `git rm --cached` to untrack — do not delete the files on disk.

## Adding a New Language

Example — adding Japanese (`ja`):

1. Create `raw-assets/ja{copy}/` mirroring the structure of `en{copy}/`
2. Replace image content with Japanese versions
3. Add `ja` to `LOCALE_BARE_ALIASES` handling in `src/modules/game/engine/game.assets.ts` if needed
4. Run `npm run validate:lang` to confirm no files are missing
5. Run `npm run assetpack` to generate output
6. Commit `raw-assets/ja{copy}/` — do not commit `public/assets/`
